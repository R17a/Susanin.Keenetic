# Веб-панель: языки интерфейса (i18n)

Панель (`www/`) многоязычная: русский (по умолчанию), английский, китайский
(упрощённый, `zh-Hans`). Выбор — в шапке справа («Язык:»), запоминается в
`localStorage['susanin_lang']`, применяется без перезагрузки страницы.

## Файлы

| файл | назначение |
|---|---|
| `www/i18n.js` | загрузчик словарей, `t()`, переключатель, применение к DOM |
| `www/lang/RU.JSON` | эталон: в нём есть **все** ключи; правки текста начинаются здесь |
| `www/lang/EN.JSON` | английский (тот же набор ключей) |
| `www/lang/ZH.JSON` | китайский упрощённый (тот же набор ключей) |

Словари — плоский JSON вида `{"ключ": "текст"}`. Ключи — только ASCII.
В тексте допустимы подстановки `{name}`, `{n}`, `{value}` и т. п.

## Подключение в коде

`i18n.js` подключается в `index.html` **первым** (в `<head>`), а `app.js` и
`config.js` стартуют свой рендер через `I18N.ready(fn)`.

```js
T('list.empty', 'список пуст')                       // ключ + русский fallback
T('memo.loaded', 'загружено записей: {n}', { n: 5 }) // с подстановкой
```

В разметке:

```html
<h2 data-i18n="cfg.title">Конфигурация агента</h2>
<input data-i18n-ph="list.filter.ph" placeholder="фильтр…">
<button data-i18n-title="app.btn.reload.tip" data-i18n="app.btn.reload">Reload</button>
<p data-i18n-html="memo.hint.html">…<code>*.domain</code>…</p>
```

Правила:
- `data-i18n` — `textContent` (не использовать на элементах с вложенными тегами);
- `data-i18n-html` — `innerHTML` (только для доверенных строк словаря);
- `data-i18n-title` — `title` (+ `aria-label`, если он есть);
- `data-i18n-ph` — `placeholder`.

Если ключа нет в словаре или словарь не загрузился (старый агент, 403/404),
показывается русский литерал из кода — панель остаётся рабочей.

## Соглашение о ключах

| префикс | что это |
|---|---|
| `app.*` | шапка, кнопки, заголовки окна |
| `status.*`, `list.*`, `memo.*` | вкладка «Статус», списки, редактор списка |
| `tab.<id>.label` / `tab.<id>.note` | закладки конфигурации |
| `grp.<tabId>.<n>` | заголовки групп полей (`n` — индекс группы в разделе) |
| `cfg.<param>.label` / `.desc` | подпись и описание поля конфига |
| `cfg.*` (прочее) | служебные строки формы конфигурации |
| `err.*`, `toast.*`, `op.*` | ошибки, всплывающие сообщения, названия операций |

Ключи полей **выводятся автоматически** из имени параметра: добавили в
`config.js` поле `f('foo', 'Подпись', 'Описание')` — в словаре нужны
`cfg.foo.label` и `cfg.foo.desc` (если описание пустое — только `.label`).

## Добавить поле / раздел

1. Дописать `f(...)` в `config.js` (подпись и описание — по-русски).
2. Добавить `cfg.<param>.label` / `.desc` во все три словаря.
3. `sh tools/check-lang.sh` — покажет забытые ключи.

Исключение — повторяющиеся блоки (сейчас это профили): у `profile1..4_*`
одинаковые подписи, поэтому они берут общие ключи `cfg.profile.<поле>.label` /
`.desc` (см. helper `pf()` в `config.js`), и перевод нужен один раз на все четыре
профиля.

## Добавить язык

1. Скопировать `RU.JSON` → `XX.JSON`, перевести значения, поправить `_meta`
   (`lang`, `name`).
2. В `www/i18n.js` добавить код в `SUPPORTED`, `NAMES`, `FILES`, `LANG_ATTR`.
3. `sh tools/check-lang.sh` — наборы ключей должны совпасть.

## Проверка

```sh
sh tools/check-lang.sh          # JSON, парность ключей, подстановки, пустые строки
python3 tools/dev-web.py        # локальная панель с мок-API: http://127.0.0.1:8080/
```

`dev-web.py`: сначала проверьте русский (он должен выглядеть как раньше),
затем EN и ZH; после перезагрузки страницы язык должен сохраниться.
Переключение при несохранённых правках в конфигурации спрашивает подтверждение.

## Что НЕ переводится

Тексты, которые формирует агент: строки лога (`/api/log`), сообщения об
ошибках API (`{"ok":false,"error":…}`), содержимое `susanin.conf`. Их перевод —
отдельная задача на стороне C-кода (см. CHANGELOG/PLAN).

# AY — закрытый транспорт выхода в Интернет

Пакет умеет ходить в Интернет через внешний сервер **Susanin.Keenetic.AY**.
Клиент в агенте поднимает собственный tun-интерфейс и держит UDP-сессию с
сервером: IP-пакеты, попавшие в tun, уходят на сервер, ответы возвращаются в
tun и ядро само раздаёт их по маршрутам (LAN, локальные сокеты). Формат и
шифрование — закрытая часть.

## Что нужно

- Сервер AY (отдельный проект) с поднятым tun и NAT. Готовая сборка —
  для Ubuntu x86-64 (см. `README-VPS.md` в комплекте); под другие ОС её
  собирают отдельно. По умолчанию: UDP/5004, сеть туннеля `10.23.0.0/24`,
  MTU 1200. Порт можно изменить в конфиге сервера и указать на роутере как
  `host:port`.
- Ключ сервера: 64 hex-символа или парольная фраза.
- На роутере — `/dev/net/tun`. Агент сам пытается загрузить модуль `tun` и
  создать узел устройства, но на некоторых прошивках это делается вручную.
- Транспорт входит в поставку в виде бинарника; исходники не публикуются.
  В сборке без него AY виден в панели, но кнопка подключения отключается с
  сообщением «транспорт не входит в эту сборку».

## Настройка через панель

1. **VPN / Egress → Susanin.Keenetic.AY**: вписать сервер и ключ. Порт по
   умолчанию 5004; если на сервере другой — укажите его прямо в поле «Сервер»
   как `host:порт` (отдельного поля порта нет).
2. Нажать **Подключиться**. Статус должен стать зелёным («подключено»).
3. **Тип egress** = `AY (Susanin.Keenetic.AY)` → **Сохранить раздел**.

После этого весь VPN-трафик идёт через AY. Прямой трафик остаётся прямым —
ровно как у `interface`/`tproxy`: тип egress выбирает путь для того, что агент
признал «через VPN».

Кнопка «Отключиться» останавливает сессию и убирает tun; правила при этом не
поднимаются, и трафик идёт напрямую, пока туннель снова не подключён.

## Ключи конфига

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `egress_type` | `interface` | `ay` — весь VPN-трафик в туннель AY |
| `ay_server` | пусто | адрес или имя сервера; можно `host:port`; пусто = выключено |
| `ay_key` | пусто | PSK: 64 hex или парольная фраза |
| `ay_port` | 5004 | UDP-порт сервера; `host:port` в `ay_server` сильнее |
| `ay_iface` | `ay0` | tun-интерфейс клиента (создаёт агент) |
| `ay_tun_ip` | `10.23.0.2/24` | адрес клиента в туннеле; должен быть в tun-сети сервера |
| `ay_mtu` | 1200 | MTU туннеля, 576..1212 |
| `ay_keepalive` | 5 | период keepalive, сек (сервер чистит сессию через 30 с) |
| `ay_mark` | `0x2` | fwmark UDP-сокета клиента: его пакеты обходят туннель |

## Как это устроено

- Агент создаёт tun `ay0`, адрес `10.23.0.2/24`, MTU 1200. Пакеты в него
  отправляет только VPN-таблица маршрутизации (`routing_table`).
- Перед tun стоит SNAT в `ay_tun_ip`: сервер находит сессию по внутреннему
  адресу назначения и без SNAT не смог бы вернуть ответ на LAN-клиента.
- Собственный UDP-сокет клиента помечается `ay_mark`; отдельное `ip rule`
  уводит эти пакеты в `main`, иначе они попали бы в тот же туннель.
- Для трафика через туннель по умолчанию включается MSS-кламп по PMTU: иначе
  крупные TCP-сегменты молча терялись бы на MTU 1200.
- Сессия держится keepalive. При молчании сервера клиент делает новый заход;
  после перезагрузки подключение восстанавливается автоматически, если тип
  egress = `ay` (или осталось «Подключиться» в `var/ay.desired`).

## Диагностика

- Панель: раздел AY и «Статус» (строка `ay:`).
- `susanin-agent status` — состояние сессии, счётчики, ошибка.
- `susanin-agent datapath status` — `ay: on (... snat=1 ip_rule=1 up=1)`.
- Журнал агента: строки `ay:` (старт, сессия, перезаход, остановка).
- `cat /opt/susanin/var/ay.status` — снимок состояния для панели;
  `/opt/susanin/var/ay.desired` — 1/0 (хочет ли оператор подключения).

Частые причины «не подключается»:

| Симптом | Что проверить |
|---|---|
| `нет /dev/net/tun` | `modprobe tun`, наличие `/dev/net/tun` |
| `не удалось разрешить <сервер>` | имя/адрес, DNS роутера |
| «нет ответа сервера» | сервер запущен, UDP/5004 открыт, ключ совпадает |
| «сервер не подтвердил ключ» | ключ на клиенте и сервере разный |
| подключено, но сайты не открываются | `egress_type=ay` сохранён; `ay_tun_ip` в tun-сети сервера; MSS/PMTU |
| `noroute` в журнале сервера | SNAT: `ay: SNAT -> ...` в `datapath status` |

## Ограничения

- Только IPv4 внутри туннеля.
- Один адрес в туннеле на роутер (`ay_tun_ip` уникален среди клиентов).
- MTU 1200: подходит для типового PPPoE, но не для путей с меньшим PMTU
  (проверяется MSS-клампом).
- Транспорт входит в поставку в виде бинарника; публичная сборка без него
  собирается с заглушкой.

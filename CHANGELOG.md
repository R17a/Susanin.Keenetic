# Changelog — Susanin.Keenetic

Все заметные изменения проекта. Формат — по версиям (новые сверху).

## v0.4.0-dev7 (не выпущено)

- **Принудительный рестарт Xray без init-скрипта — через kill из C (повторная
  проверка).** В прошлой правке fallback-ветка использовала `sh -c`-цикл по
  `/proc`, а в её же командной строке есть литерал запуска Xray
  (`... xray run -config .../xray-tproxy.json`) — цикл находил САМ СЕБЯ и убивал
  свой shell, Xray не поднимался. Теперь процесс ищется и снимается из C
  (`xray_kill_all()`, `kill(pid, SIGKILL)`), затем запуск; сопоставление «наш
  Xray» вынесено в `backend_is_our_xray_cmdline()` и покрыто тестом (агент, `grep`
  по пути, `vi`/`tail` конфига и сам shell-цикл не считаются Xray). Поиск процесса
  в `S93xray-tproxy` и `soak.sh` тоже требует наличия `run`, чтобы совпадение с
  `grep` по шаблону было невозможно.

- **Правки по повторной проверке Claude (port-aware).** Элемент набора
  `hash:ip,port` теперь пишется с протоколом — `ip,udp:порт` / `ip,tcp:порт`
  (без протокола ipset считает элемент TCP, и UDP-пакеты с ним не совпадали);
  `sweep_direct` в pair-режиме ищет записи состояния по паре `ip:порт`;
  `never_state_clean` разбирает ключ перед проверками `vn_has`/`st->never`
  (они работают с голым адресом); `watch` ведётся по тому же ключу, что и
  снятие (иначе в pair-режиме записи жили до TTL); при смене `port_aware`
  устаревшие ключи другого формата не пишутся в наборы (ошибок ipset больше
  нет); принудительный рестарт Xray работает и без init-скрипта (снятие по
  `cmdline` с приёмом `[x]ray`). Устаревшие формулировки про «агент пока не
  передаёт порт» убраны; добавлен `.editorconfig` (`charset = utf-8`), чтобы
  BOM в скрипты больше не возвращался.
- **Короткие команды `susanin …` (NEW).** Установщик и
  `susanin.sh update` создают симлинк `/opt/bin/susanin` →
  `/opt/susanin/tools/susanin.sh` (`/opt/bin` у Entware уже в `PATH`), поэтому
  вместо длинного пути работает короткий вызов: `susanin status`, `susanin check`
  (состояние датаплейна), `susanin diagnose`, `susanin report`, `susanin restart`.
  Чужой файл с именем `/opt/bin/susanin` не перезаписывается; при удалении симлинк
  снимается только если ведёт на наш скрипт. В `tools/susanin.sh` добавлены
  подкоманды `check`, `diagnose`, `report`; в `TESTBUILD.md` — раздел про короткие
  команды.

- **Port-aware identity — этапы 1–3 из 5 (по умолчанию выключено).**
  Ключ `port_aware` (0 — поведение прежнее, решения по адресу целиком);
  `tools/datapath.sh` — наборы `hash:ip,port` с матчем `dst,dst`, миграция типа
  набора, `add|del <ip> [<порт>] <tcp|udp> …`; состояние — ключи `ip:port`
  (`state_key()`/`state_key_split()`), старый файл состояния читается как раньше;
  классификатор принимает решения по паре `(dst,dport)`, backend передаёт порт в
  ipset; адресные пины (`vpn_always`, `dns_sniff`, снятие по `vpn_never`) в
  pair-режиме уходят в `susanin_ok_net` (матч по `dst`), потому что ok/test стали
  парами; ре-ассерт состояния и чистки движка разбирают ключи. Осталось:
  наблюдаемость этапа 4 сделана: status предупреждает про память, diagnose.sh печатает тип набора susanin_ok_tcp и подсказывает, что нужно перезапустить при смене режима, в панели появилось поле port_aware, в config.example.conf — пояснение. Осталась проверка на стенде и сборка; раздел «port_aware — экспериментально» добавлен в TESTBUILD.md (что включить, за чем следить, что прислать и как откатить).
  Заодно исправлены найденные харнессом дефекты `datapath.sh`: `[ … ] && присваивание`
  под `set -e` обрывало скрипт при ложном условии, а `add|del` падали без последнего
  аргумента (`set -u`).

- **Правки по внешнему разбору (Claude).** Резервный запуск Xray в вотчдоге вообще
  не срабатывал: `sh -c`-цикл по `/proc` находил **сам себя** (в его командной
  строке есть путь к конфигу) и делал `exit 0` — теперь наличие процесса
  проверяется из C (`xray_proc_exists()`), а совпадение требует и `xray`, и
  `run -config`, и наш конфиг (открытый `vi xray-tproxy.json` больше не выглядит
  как Xray). Живой, но не слушающий порт Xray после 3 проверок принудительно
  перезапускается (S93 умеет `kill -9` и не стартует при D-state), а сам перезапуск
  из вотчдога теперь асинхронный — раньше он мог блокировать главный цикл агента
  до ~17 с. В Memo-редакторе: «Сохранить» заблокирована до успешной загрузки списка
  (сбой загрузки больше не может стереть список), файл больше 64 КБ честно отдаёт
  `413` (а не обрезанный текст), оборванное тело запроса отклоняется (`400`, список
  не меняется), текстовые ответы `401/413` показываются понятной ошибкой, а
  сохранение без изменений не перезаписывает `.bak`. `precision` больше не трогает
  `learn_strict` и сообщает о неизвестном пресете (stderr + `config show`);
  уборка старого формата бэкапов удаляет только `archive/datapath-*.tar.gz`;
  `soak.sh` измеряет RSS/CPU именно нашего Xray. Добавлены host-тесты:
  `test_config` (пресет), `test_ops` (проверка `ip rule` с маской), `test_web_list`
  (один `.bak`, уборка копий, подсчёт строк) — `make test` гоняет четыре набора.
- **Бэкапы больше не размножаются** (папка `archive` забивалась
  копиями). Снимок правил netfilter — теперь ОДИН каталог
  `/opt/susanin/var/datapath.bak` (файлы перезаписываются; если правила не
  изменились, не пишем вообще). Прежний формат (`datapath-<дата>` + ротация
  `var/archive/*.tar.gz` «3 каталога / 5 архивов») удаляется автоматически при
  первом `up`; маркер `.last-backup` и лимит «не чаще раза в час» больше не нужны.
- **Один `.bak` на список.** Правка `vpn_always`/`vpn_never` (в том числе из
  панели) писала полную копию `<список>.bak-ГГГГММДД-ЧЧММСС` на КАЖДУЮ правку —
  даже когда содержимое не менялось. Теперь бэкап один — `<список>.bak`, и
  пишется только при фактическом изменении (права исходного файла сохраняются);
  накопленные копии старого формата удаляются при установке/обновлении и при
  первой правке списка.
- **Memo-редактор списков в веб-панели (W5).** Кнопка «Редактор» в каждой колонке
  открывает весь файл текстом. Новые эндпоинты: `GET /api/list/raw` (сырой текст,
  с комментариями) и `POST /api/list/save` (тело до 64 КБ — раньше запрос читался
  в буфер 4096, и большой список молча обрезался). Пустые строки и `#`-комментарии
  сохраняются, нераспознанные строки отбрасываются (в ответе `kept`/`dropped`,
  панель показывает предупреждение), запись атомарная, после сохранения — SIGHUP
  агенту. Сохранение доступно только с токеном (иначе `401`).
- **Xray: чужой процесс не трогаем.** `S93xray-tproxy stop` делал `kill` по всем
  PID с именем `xray` — мог остановить чужой Xray (XKeen и т.п.), а `start`
  принимал чужой процесс за свой. Теперь свой PID пишется в
  `/opt/susanin/var/xray.pid` и сверяется с `cmdline` (наш конфиг); fallback —
  поиск по `/proc/*/cmdline`. Если порт занят чужим процессом — честное
  предупреждение, но чужой Xray не убиваем. То же в `tools/xray-egress.sh`, в
  вотчдоге агента (`pidof xray` → проверка по конфигу) и в `diagnose.sh`
  (различает «наш Xray не запущен» и «есть чужой процесс»). Добавлена ветка
  `S93xray-tproxy status`.
- **Защита от накопления процессов Xray (зависание роутера).** Симптом
  2026-10-10: в `top` — ~14 процессов `xray run -config …/xray-tproxy.json` (часть
  в состоянии `D`), память `101M/122M`, `load average` ~20, интернет встал. Причина:
  поиск своего процесса через `pidof xray` (апплета может не быть в окружении
  init-скриптов) и один `SIGTERM` без ожидания — новый экземпляр поднимался поверх
  не завершившегося старого. Теперь `stop` ждёт завершения и добивает `kill -9`,
  `restart` отменяется, если старый процесс жив, а вотчдог агента не поднимает
  новый экземпляр, пока есть процесс с нашим конфигом (в логе — `процесс Xray
  есть, но :порт не слушает — повторный запуск пропускаю`). Раздел «Роутер
  зависает: в top много процессов xray» добавлен в `TROUBLESHOOTING.md`.
- **`status`/`apply` больше не рапортуют ложное `MISSING`.** Правила добавляются с
  маской (`fwmark 0x20000000/0x30000000`), а проверки искали форму без маски:
  `status` показывал `MISSING`, `apply --dry-run` — всегда `OUT OF SYNC`, а
  `apply` зря пересоздавал правило (короткое окно без него). Хелпер
  `rule_fwmark_present()` ищет обе формы; применён в `ops_status` и
  `check_missing`.
- **`[ -n "ipt" ]` → `[ -n "$IPT" ]`** в `tools/datapath.sh`: проверка наличия
  `iptables` была мёртвой (литерал вместо пути), сообщение `iptables not found`
  недостижимо, а при отсутствии `iptables` скрипт падал каскадом ошибок вместо
  `exit 2`.
- **`diagnose.sh` и `lan_server_interfaces`.** Штатная поддержка «WDTT как LAN»
  сама переносит `wdtt0/wdttraw0` в `lan_interfaces`, но диагност советовал их

  `lan_server_interfaces` предупреждения нет: проверяется `mss_clamp` и
  напоминается про политики Keenetic (`ip rule` 409x).

  `susanin-agent diag errors` (было

## v0.4.0-dev6 (не выпущено)

- **tproxy: неудача в test-фазе теперь обнаруживается.** Условие «провала»
  требовало `rp == 0` (SYN_SENT) или `rp <= 1` (ESTABLISHED), но в tproxy ответы
  приходят от локального Xray, поэтому адрес не подтверждался и не уходил в
  cooldown: через `test_ttl` запись исчезала и цикл «promote → ct_delete»
  повторялся. Теперь в tproxy неудачей считается ESTABLISHED без реальных данных
  (`rb < 128` при достаточном объёме отправленного) — срабатывает cooldown. Чтобы
  это не срабатывало ложно на медленном апстриме (за первый RTT клиент отправляет до
  начального окна TCP ≈10 сегментов без ответа), неудача признаётся не раньше, чем
  запись в `test` прожила 3 с (`state_at()`: создание = `expire − test_ttl`, запись
  в `test` не продлевается).
  Условие «провала» для `ok` в tproxy недостижимо и оставлено как есть: такие
  записи просто истекают по TTL. `vn_refresh2()` обнуляет флаг `changed` в начале
  (при раннем выходе он больше не остаётся от прошлого вызова).
- **Правки по третьему разбору.** Пины dns_sniff (и префиксы CDN/media) писались в
  state через `state_add(..., refresh=1)`, а он отсутствующую запись не создаёт —
  из-за этого `st.never` был всегда пуст (проверки `state_has(&st->never)` не
  работали, пины после `resync_sets` не восстанавливались). Добавлен хелпер
  `state_touch()` (создать или продлить) и применён во всех таких местах.
  Подтверждение `ok` в tproxy больше не считается по числу ответов (`rp >= 2`):
  локальный Xray отвечает SYN-ACK/ACK даже при мёртвом апстриме — теперь требуются
  реальные данные (`rb >= confirm_min_bytes`), для «здоровья» — `rb >= 128`.
  Тяжёлая чистка state по списку `vpn_never` вызывается только при фактическом
  изменении набора (`vn_refresh2()` сообщает об этом), а не каждые 200 мс.
  Счётчики лидерства сбрасываются при failover; кэш списков освобождается при
  остановке снифинга.
- **Фаза 1 плана Dev6 (обучение).** Перед заворотом адреса в VPN — дешёвая прямая
  TCP-проба (только при сбое рукопожатия, бюджет 10/мин): отвечает напрямую — не
  заворачиваем. `sweep_direct()` получил фильтры обучения (служебные порты
  53/853/500/4500/8567, приватные адреса, `test`/`watch`, «мягко-прямо»).
  `resync_sets()` пишет остаток TTL, а не полный; добавлен периодический
  `state_expire()` — протухшие записи больше не копятся.
- **Персист состояния.** `susanin_ok_net` (CDN/media-префиксы), `susanin_direct` и
  пины `dns_sniff` в `susanin_never` — в state: переживают re-provision,
  fail-open и рестарт. Конфликт «ok ↔ vpn_never» снимает адрес из VPN-наборов и
  чистит его conntrack.
- **Фаза 2 (health/fail-open/race).** Пробы egress вынесены в отдельный процесс —
  главный цикл не блокируется (было до ~4–5 с на тик). Состояние кандидата — по
  доле успехов за окно (порог 30 %), а не по одному ответу. Race переключается
  только после 3 тиков лидерства; один `ct_flush` на тик. Fail-open (все egress
  down и пропажа Xray в tproxy) чистит conntrack VPN-метки. В tproxy добавлена
  проверка апстрима Xray через локальный SOCKS5 — мёртвый апстрим даёт
  fail-open/failover.
- **Фаза 3 (агрегация).** Префикс CDN/media уходит в `ok_net` после
  `aggregate_confirm` (по умолчанию 2) разных адресов; таблица фиксированная (64)
  — память не растёт. `vn_recent`/`of` оставлены в памяти (осознанно), но при
  переполнении вытесняется одна запись, а не вся таблица.
- **`egress_race_list` удалён** (ключ нигде не использовался — кандидаты race
  берутся из `egress_interface`): убран из конфига, `config.example.conf`,
  веб-панели, `install.sh`/`update.sh`.
- **Веб-панель: сохранение ключей, которых нет в конфиге.** Панель правила только
  ключи, уже присутствующие в `susanin.conf` (создавать разрешалось лишь
  `profileN_*`), поэтому переключатель/поле из старого конфига молча не
  сохранялось: «Сохранено», а после перезагрузки — прежнее значение. Теперь можно
  создать любой ключ с корректным именем (кроме `web_token`/`web_listen`): bool —
  всегда, остальные — только с непустым значением. Ответ `POST /api/config`
  сообщает непринятые ключи (`skipped`), панель показывает их в предупреждении,
  недоступный переключатель визуально приглушён.
- **Тесты и диагностика для длительного прогона.** `make test` — тест парсера
  conntrack (`tests/test_conntrack.c`) на сэмплах
  `testdata/nf_conntrack.samples` (TCP ESTABLISHED/SYN_SENT/«тишина после
  рукопожатия», UDP, ICMP+FASTNAT, IPv6, hex-метка, битые строки; хост-компилятор,
  в кросс-сборку не входит). `tools/soak.sh` — суточный прогон с записью метрик
  (RSS/CPU агента и Xray, размеры наборов, conntrack, рост и ошибки лога, место,
  load) и сводкой роста КБ/ч по Ctrl-C.
- **`vpn_always.txt`: дополнен блок OpenAI/ChatGPT и Anthropic/Claude.** Добавлены
  явные имена, которых не было (`chat.com`, `sora.com`, `oaistatsig.com`,
  `android/ios.chat.openai.com`, `*.livekit.cloud` для голоса, CDN/Azure-хосты
  OpenAI, `browser-intake-datadoghq.com`, `servd-anthropic-website.b-cdn.net` и
  др.). Сеть `160.79.104.0/21` в списке уже была — она шире запрошенного `/23`,
  поэтому дубль не добавлялся; IPv6-сети (`2607:6bc0::/48`, `2607:6bc0:11::/48`)
  закомментированы — в v1 резолвим только A-записи. `install.sh` при обновлении
  дополняет существующий список новыми строками, старые не трогает.
- **Обновление дополняет списки Always/Never.** `tools/update.sh` (`susanin.sh update`)
  теперь, как и `install.sh`, дополняет `vpn_always.txt` **и** `vpn_never.txt`
  новыми строками из пакета: существующие и пользовательские строки не трогаются,
  добавленные помечаются комментарием `susanin-update:`, повторный запуск ничего
  не меняет. Если файла списка нет вовсе — он ставится из пакета. Ищет файлы и в
  плоском релизном архиве, и в dev-архиве (списки в `etc/`). Раньше `update.sh`
  дополнял только `vpn_never`, а `vpn_always` не трогал вовсе.
- **Установщик: исправлена выборочная распаковка (GNU tar).** `bootstrap.sh`
  передавал tar'у в списке имена каталогов: GNU tar, получив каталог, вычитывает
  архив до конца, а остальные имена после этого считает ненайденными и возвращает
  код 2 — установка падала с сообщением «не умеет распаковывать выбранные файлы»
  (роутер с Entware `tar` 1.35, хотя он это умеет). Теперь в список попадают
  только файлы (каталоги tar создаёт сам), а успех распаковки проверяется по
  наличию нужного бинарника, а не по коду возврата. Проверено на dev-архиве
  (mipsel/aarch64/x86_64) и на плоском релизном архиве. Заодно убран устаревший
  текст про «~85 МБ»: полная распаковка — ~5 МБ, выборочная — ~1,5 МБ.
- **Правки по разбору (хотфикс dev6).** Прямая проба — только для причины «SYN без
  ответа»: для `DPI-RST`/`TCP-CLOSE` она давала ложное «прямо отвечает» (при
  блокировке по SNI рукопожатие проходит), и адрес не заворачивался в VPN. Добавлен
  негативный кэш (300 с), лимит 2 пробы/с, а при исчерпании бюджета адрес осознанно
  не заворачивается 120 с. `vn_has()` — проверка **текущего** `susanin_never`

  CDN/media снова попадают в state (при создании `refresh=0`) и продлеваются при
  повторе. `st.never` чистится по TTL и ограничен 4096 записями. Подтверждения
  агрегации: до 3 адресов и окно 10 минут (раньше A,B,A,B считались новыми). Кэш

  `mss_clamp=0` не делаем ничего. Для PPPoE можно явно задать

- **CDN-агрегация больше не перекрывает `vpn_never`:** префикс не агрегируется,
  если сам адрес в `vpn_never`.
- **`pin_reassert` реализован** — периодический ре-ассерт пинов
  `vpn_always`/`vpn_never` (самолечение без ребута).
- **Watchdog Xray независим от датаплейна:** после падения Xray (`dp_ok=0`)
  агент больше не остаётся в fail-open навсегда — поднимает Xray с backoff.
- **`ok_ttl` по умолчанию конечный** (`config.example.conf` был `0`).
- **Кэш `vpn_always`** сбрасывается при изменении файла (устаревшие сети
  снимаются сразу).

- **`diagnose.sh`:** предупреждение MTU/MSS (WAN MTU<1500 без clamp) и показ
  цепочки `SUSANIN_MSS`.
- **Быстрый re-provision** датаплейна после сноса правил NDM (проверка раз в 5 c).
- **D1 — мягкое «прямо» (`auto_direct`).** Если адрес в VPN (ok) деградирует, он
  временно принудительно идёт прямо (`susanin_direct`, TTL), а при деградации
  прямого пути возвращается в обучение/VPN.
- **M1 — класс media (IPTV/видео, `media_enabled`).** Детект по форме потока и
  агрегация префикса в VPN — последующие потоки идут через VPN с первого пакета
  (без FASTNAT-залипаний).
- **IPTV (megatv): сети провайдера — в `vpn_always`.** В поставку добавлены
  сети серверов видеопотока (`206.123.140.0/24`, `45.156.223.0/24`,
  `194.35.227.0/24`, `195.211.191.0/24`) — чтобы IPTV шло через VPN (прямой
  путь у провайдера периодически режется, «то плавно, то лагает»). `install.sh`

  трогает). В `vpn_never` эти адреса класть нельзя — там принудительный DIRECT.
- **Исправлено: мобильный Битрикс и IPsec уходили в VPN.** Служебные UDP-порты
  **500/4500** (IPsec IKE/NAT-T) и **8567** (UDP-мессенджер Битрикс24) теперь
  всегда идут напрямую: `RETURN` в цепочке `SUSANIN` (до правил наборов) и
  исключение из автообучения по `sport`/`dport`. Раньше сервер мобильного
  Битрикса (Akamai) попадал в `susanin_ok_udp`, и `udp-relay` отправлял его
  через Xray; IPsec за роутером в LAN так же уходил в релей. `learn_exclude_ports`
  по умолчанию дополнен `500,4500,8567`.
- **Возврат на основной VPN (failback, Master/Slave).** Список
  `egress_interface=nwg2,nwg0` — первый egress приоритетный: если он упал,
  трафик уходит на резервный (failover, как раньше), а когда снова поднялся —
  автоматически **возвращается** на него (failback), без ручного `reload`.
  Антидребезг — `egress_failback_debounce` (по умолчанию 30 с, «UP держится N
  секунд»); отключить возврат — `egress_failback=0`. Health проверяет каждый
  egress независимо (привязка к интерфейсу); в логе — `egress <X> DOWN,
  failover -> <Y>`, `egress <X> UP`, `... (failback)`.
- **Watchdog Xray.** Если при `egress_type=tproxy` Xray перестал слушать порт,
  агент сам поднимает его с backoff (init-скрипт `S93xray-tproxy restart` или
  прямой запуск бинаря), а не только снимает правила. Ключ `xray_watchdog=1`.
- **Память Xray на слабом роутере.** Ключи `xray_gogc` (по умолчанию 50) и
  `xray_gomemlimit` (64MiB): Xray запускается с агрессивным GC и мягким лимитом
  памяти. `diagnose.sh` показывает `free`, swap/zram, топ по RSS и случаи OOM
  из `dmesg` с рекомендациями.
- **`xray-egress.sh start` и `restart`.** `start` — синоним `enable`; `restart`
  перезапускает **только Xray и агента**, не меняя режим (`egress_type`) и не
  трогая `vpn_always`. Закрыт вопрос «есть STOP, почему нет START».
- **DNS-снифинг (`dns_sniff`).** Зеркальный захват DNS-ответов LAN через
  AF_PACKET (штатный DNS не перехватываем): таблица `домен -> IP`, и адрес из
  ответа сразу пинится, если домен попадает в `vpn_always`/`vpn_never` — так
  поддомены покрываются до их собственного резолва. По умолчанию выключен
  (`dns_sniff=0`); настройки `dns_sniff_ttl`, `dns_sniff_iface`.
- **Kernel-offload.** При `kernel_offload=1` и заданном `kernel_egress`
  адреса из `susanin_ok_net` уводятся маршрутом через настоящий интерфейс, минуя
  userspace tproxy (быстрее на слабом CPU). Отдельная метка/таблица; состояние
  видно в `status`/`diagnose`.
- **Race-пробинг egress (`egress_race=1`).** Агент замеряет всех живых
  кандидатов и выбирает быстрейшего; в логе — `race: <A> -> <B> (fastest Nms)`.
- **Профили маршрутизации, полноценный слой.** Профиль задаётся ключами

  живом egress из списка `profileN_egress`. `profileN_auto=1` — автообучение на
  профиль: подтверждённый адрес, попадающий в CIDR/IP профиля, пинится в набор
  `susanin_prof_<name>`. Профили видны в `status`/`diagnose`.
- **Профили: гео-списки и shell.** `profileN_geo_url` — скачиваемый CIDR-список

- **MSS/PMTU для туннеля/CDN.** Ключи `mss_clamp` (`0`=выкл, число байт,

  возвращаются; желаемые адреса/сети передобавляются каждый проход (`ipset
  -exist`), так что внешняя потеря пина само-исправляется (иначе сайты из списка
  уходили напрямую, напр. Claude).
- **Авто-детект блокировки по SNI.** Новый сигнал `FAST/DPI-RST` —
  «TCP-рукопожатие прошло, ClientHello отправлен, ответа нет, соединение
  сброшено» → адрес уводится в VPN (раньше такие блокировки не ловились).
- **`deepseek.com` → `vpn_never`** (всегда напрямую): через VPN API DeepSeek
  недоступен (это ломало работу Kilo в VS Code).
- Пересобраны бинарники (mipsel/mips/aarch64/armv7/x86_64), обновлены
  `develop/SHA256SUMS` и `develop/susanin-keenetic-0.4.0-dev.tar.gz`.

## v0.3.10

- **Меньше «дёрганья» VPN-списка (`ok_evict_misses`).** Раньше адрес мог
  вылететь из списка «идёт через VPN» после одного плохого наблюдения и тут же
  вернуться — список «мельтешил». Теперь адрес убирается только после нескольких
  сбоев подряд (по умолчанию 3). В логе будет одна сводка раз в ~5 минут, а не
  строка на каждое событие. Хотите как раньше — поставьте `ok_evict_misses=1`.
- **Быстрее заворачиваем «заглохший» HTTPS.** Частая картина: сервер ответил, но
  данные почти не идут — так провайдер замедляет соединение. Теперь такой адрес
  сразу проверяется через VPN, не дожидаясь окна наблюдения. Проверки идут чаще:
  `soft_interval` по умолчанию снижен до 1 секунды.
- **Ограничитель лишних переводов в VPN (`promo_per_min`).** Чтобы быстрый
  детект не завернул в VPN всё подряд, за минуту делается не больше 30 новых
  проб (настраивается; `0` — без ограничения).
- **Мессенджеры не «выпадают» из VPN.** Telegram/WhatsApp держат соединение
  долго; раньше один «тихий» срез мог убрать адрес из списка VPN. Теперь — нет.
- **Диагностика одной командой.** `sh /opt/susanin/tools/diagnose.sh` сам
  проверит, всё ли на месте (пакеты, настройки, правила, списки), и подскажет,
  что поправить.
- **Сменили или удалили VPN — перезапуск не нужен.** `susanin.sh reload`
  перечитывает настройки, `susanin.sh rescan` заново находит LAN и VPN,
  обновляет конфиг и применяет изменения. Если VPN-интерфейс пропал, программа
  сама переключится на живой; если живых нет — пустит трафик напрямую и напишет
  об этом в лог.
- **Установщик сам предложит доустановить нужное.** Если не хватает `ipset`,
  `iptables`, `conntrack` или сертификатов, установщик спросит, поставить ли их
  через `opkg` (флаг `--deps` — без вопроса).
- **Меньше строк в логе про списки.** Домены без A-записи (частая история у CDN)
  больше не печатаются по строке каждый — будет одна сводка, а повторные неудачи
  проверяются реже (до 1 часа). Если у домена из `vpn_always` нет A-записи на
  самом домене, программа сама проверит поддомены — так адреса CDN чаще попадают
  в VPN.
- **DNS для разбора списков.** Если системный DNS — `127.0.0.1` (NDM) или пуст,
  берётся адрес LAN-моста: в ряде сборок так надёжнее.
- **Правки `vpn_always` срабатывают сразу.** Когда адрес только что переведён в
  VPN, старые прямые соединения к нему разрываются — клиент переподключается уже
  через туннель (для `vpn_never` так было и раньше).
- **Адрес из `vpn_never` не «прыгает» в VPN.** Если адрес был в списке «всегда
  напрямую» и оттуда убран, какое-то время он не будет выучен в VPN.
- **Документация.** Добавлены `USER_GUIDE.md` (руководство) и
  `TROUBLESHOOTING.md` (что делать, если не работает).

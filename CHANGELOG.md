# Changelog — Susanin.Keenetic

Все заметные изменения проекта. Формат — по версиям (новые сверху).

## v0.3.9

Диагностика, устойчивость запуска и несколько VPN-подключений.

- `susanin-agent status`: первой строкой печатается версия (`susanin-agent X.Y.Z`) —
  больше не нужно запускать `version` отдельно;
- новый сборщик отчёта для багрепортов `tools/report.sh` (сохраняет в
  `/opt/susanin/var/report.txt`): ставится установщиком и `update` в
  `/opt/susanin/tools/report.sh`, входит в релизный архив; в описании релиза
  добавлен раздел «Диагностика»;
- датаплейн: при сбое `datapath.sh` в лог теперь пишется **причина** (последняя
  строка вывода скрипта), а не только «datapath provisioning failed»;
- preflight при старте: проверяются `iptables`, `ipset`, `conntrack`, `ip` и
  существование egress-интерфейса; при проблеме — понятная ошибка с подсказкой
  (`opkg update && opkg install …`, проверьте `egress_interface`);
- если датаплейн не поднялся, повтор раз в 60 с (вместо каждых 15 с с вводящим в
  заблуждение «data plane missing (NDM rebuild?)»); если ранее рабочий датаплейн
  исчез — поведение прежнее;
- **несколько egress (VPN) и фейловер**: списки через запятую, адреса — по
  индексу, например `egress_interface=nwg0,nwg1` и
  `egress_address=10.8.1.1,10.8.1.2`.
  Демон проверяет активный туннель и при падении переключает default в VPN-таблице
  на следующий живой egress, сбрасывая conntrack для потоков с VPN-меткой; когда
  живых не остаётся — fail-open (напрямую);
- **`disk_mode` (normal|soft)**: установщик определяет носитель `/opt` (USB/SD vs
  внутренняя память NAND/UBIFS) и для внутренней включает `soft` — лог-файл не
  ведётся, `state` не сохраняется, бэкапы/архивы не создаются (минимум записей на
  диск; цена — кэш обучения не переживает перезагрузку);
- **реакция на изменения `vpn_never`/`vpn_always`**: при добавлении IP в
  «всегда напрямую» демон сбрасывает conntrack по этому IP и убирает его из
  `ok`/`test`-кэша (иначе старые потоки остаются в VPN, особенно при
  FASTNAT/hwnat); если домен из `vpn_never` не резолвится — теперь WARN, что он
  фактически не защищён;
- **`learn_exclude_ports`**: порты, для которых отключено **быстрое** автообучение
  (детект «одиночный SYN без ответа» — так выглядит скан-шум; по умолчанию
  22, 23, 53, 445, 554, 3389 и т.п.). Меньше мусора в `ok`-кэше; «мягкое»
  обучение (потоки с ответами, которые затем тормозят) по этим портам остаётся,
  веб (80/443/QUIC) обучается как раньше. Для гарантированного обхода на таком
  порту — добавьте сервис (домен/IP/CIDR) в `vpn_always.txt` (список не зависит
  от порта).

## v0.3.8

Исправление регрессии автообучения (вошла в v0.3.5) и мелкие дефекты:

- **возвращён rate/late-stall-детект** (`classifier.c`): потоки, которым DPI
  отдал ответ, но затем «заглох» (типичный троттлинг), снова уходят в VPN
  (`SOFT TCP-LATE-STALL`, `QUIC-LATE-STALL`); пороги `TCP-CLOSE`/`TCP-STALL`
  снова `rp <= 2 && rb < 256`. Это возвращает автообучение CDN-поддоменов,
  из-за чего переставали работать превью/видео YouTube, а также медиа
  x.com/Instagram — включая клиентов OpenConnect (`oc0`), где трафик к
  Fastly/Akamai-EDGE уходил DIRECT и тормозил. На `vpn_always`/`vpn_never` и
  wildcard-зоны не влияет;
- **hysteresis списков** (`vpn_always`/`vpn_never`) считает интервалы, а не
  вызовы `va_refresh`/`vn_refresh`: раньше порог «2 обновления подряд»
  достигался за доли секунды (функция зовётся многократно за интервал) и churn
  не подавлялся;
- `vpn_never.txt`: имена приводятся к нижнему регистру (как в `vpn_always.txt`) —
  дедуп и сравнение зон больше не зависят от регистра;
- `datapath.sh status`: правильное число адресов в наборах (ipset) — раньше
  показывало 125 вместо 2682;
- `susanin-agent status`: в блоке «ipset sizes» число адресов в наборах верное
  и при большом количестве адресов (раньше могло занижаться), плюс добавлен
  набор `susanin_never`.

## v0.3.6

- **wildcard-записи** в `vpn_always.txt` / `vpn_never.txt`: строка
  `*.example.com` покрывает домен и поддомены (резолв apex + wildcard-проба
  `susanin-XXXX.example.com`); точная строка `example.com` по-прежнему означает
  только сам домен (поддомены — адаптивно);
- **конфликт зон** между файлами: если одна и та же (или пересекающаяся —
  например `*.keenetic.ru` и `forum.keenetic.ru`) зона есть и в `vpn_always.txt`, и в
  `vpn_never.txt`, приоритет отдаётся «напрямую» (`vpn_never`), в лог пишется
  предупреждение;
- ротация лога: `susanin.log` >5 МБ → сжатые архивы `susanin.log.1.gz..3.gz`
  (старые удаляются); старые каталоги `datapath-*` архивируются в
  `/opt/susanin/var/archive/` (3 свежих каталога и 5 архивов);
- меньше «дрожания» списков: адрес убирается из наборов только если он
  отсутствует **2 обновления подряд**; per-IP записи `pin/unpin` перенесены в
  `DEBUG` (в `INFO` — только итоговая строка).

## v0.3.5

- логика кандидатов ужесточена: сайты, **ответившие по основному каналу**,
  больше не переводятся в VPN (убраны срабатывания `TCP-CLOSE`/`TCP-STALL`/
  `QUIC-LATE-STALL` для потоков с ответом). Кандидатами остаются только
  направления **без ответа**; `vpn_always.txt` по-прежнему всегда через VPN.
- новый список **`vpn_never.txt`** («всегда напрямую», never VPN):
  домен / IPv4 / CIDR → ipset `susanin_never` + `RETURN` в цепочке `SUSANIN`
  до маркировки; такие адреса не попадают в `ok`/`test`;
- команда **`susanin.sh forget <ip>`** — убрать адрес из кэша и наборов;
- установщик копирует `vpn_never.txt` только если файла ещё нет;
- **OpenConnect** (ocserv, интерфейс `oc0`): установщик по-прежнему находит
  сервер и предлагает добавить интерфейс `oc0` в `lan_interfaces`, а подсеть
  клиентов — в `lan_subnets`; трафик клиентов обрабатывается как LAN (отдельные
  NAT-правила не нужны). Добавлен раздел «OpenConnect VPN на том же роутере» в
  README; проверено с клиентом (телефон по сотовой сети к роутеру).

## v0.3.0

**Установка и обслуживание**
- установка одной строкой (`install.sh`) с автоопределением архитектуры и
  LAN/VPN-интерфейсов (при неоднозначности — вопрос);
- офлайн-режим: `sh install.sh` из распакованного архива;
- `update` (конфиг и кэш сохраняются) и `uninstall [--purge]`;
- `susanin.sh stop` — graceful (SIGTERM, затем KILL).

**Сборки**
- per-arch архивы: mipsel, mips, aarch64, armv7, x86_64 + `SHA256SUMS`;
- GHCR: `ghcr.io/r17a/susanin.keenetic`.

**Дистрибутив**
- в комплекте `vpn_always.txt` (домены «всегда через VPN»); при install/update
  существующий файл не перезаписывается.

## v0.2.0

**Перенесено из родительского Susanin (MikroTik) v0.12.0**
- CIDR-строки в списке «всегда через VPN» (`a.b.c.d/n`) — отдельный ipset
  `susanin_ok_net` (маркируется для TCP и UDP, чистится/восстанавливается
  вместе с остальными пинами);
- bounded GC: лимит ok-кэша `ok_max_entries` (по умолчанию 4096 на протокол);
- graceful shutdown: по SIGTERM/SIGINT кэш сохраняется в state-файл.

**Наши доработки**
- health-устойчивость: `health_interval=5s`, `health_miss_debounce=4`;
- временные метки `HH:MM:SS` в логе демона;
- init-скрипт `S94susanin` без зависимости от `rc.func`;
- мультиархитектурная сборка: `tools/wsl-build.sh mipsel mips aarch64 armv7 x86_64`;
- `susanin_ok_net` в выводе `status`.
